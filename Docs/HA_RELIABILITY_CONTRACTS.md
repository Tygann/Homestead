## Official contracts and capability boundaries

- Mandatory feature bits follow [cover](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/cover/const.py), [fan](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/fan/const.py), and [climate](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/climate/const.py). Entity availability, usable attributes, and service discovery are additional gates. Climate HVAC mode selection has no feature bit; advertised membership is required. Capability loss never prunes saved cards.
- [Mobile webhook contracts](https://github.com/home-assistant/core/blob/dev/homeassistant/components/mobile_app/webhook.py) define registration updates, `get_config`, encryption, and `fire_event`. Freshness compares complete successful update metadata, including app version/build, device/OS information, and push details. Successful route refresh replaces both optional Cloud URLs, clearing omitted values while preserving webhook identity and Keychain secrets. Registration and recovery remain single-flight.
- [WebSocket commands](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/websocket_api/commands.py) acknowledge `subscribe_entities` before its compact initial event. Missing entities are omitted; an empty selection means all entities. Homestead skips empty selections, bounds selection to 64 IDs and socket lifetime to 15 seconds, consumes the snapshot, unsubscribes, and closes. Explicitly unsupported commands use legacy fallback. Sensor Boards batch selections per server.
- [Registry contracts](https://github.com/home-assistant/core/blob/dev/homeassistant/helpers/entity_registry.py) expose stable registry UUID `id` and rename event `old_entity_id`. Ordered live events update references in place. Local per-card/profile UUID bindings recover offline changes, including reused old entity IDs. Missing entities keep cards; absent prior bindings cannot safely be inferred. Dashboard schema, backup/quarantine recovery, newer-schema protection, and iCloud encoding remain unchanged.
- [Notification actions](https://companion.home-assistant.io/docs/notifications/actionable-notifications/) define buttons, replies, authentication/destructive options, and `mobile_app_notification_action` events. The delegate awaits background delivery; cold-launch navigation is queued. Cancellation/default taps do not fire actions. Originating webhook identity wins over active-profile state; removed/ambiguous origins cannot receive actions.
- [Core relay payloads](https://github.com/home-assistant/core/blob/dev/homeassistant/components/mobile_app/notify.py) include `registration_info.webhook_id`. Local Worker changes forward this and select the content-extension category while retaining data and ordinary alert delivery. The [official iOS content extension](https://github.com/home-assistant/iOS/blob/main/Sources/Extensions/NotificationContent/NotificationViewController.swift) provides precedent for dynamic native actions. These relay changes are not deployed.
- [Webhook WebSocket handling](https://github.com/home-assistant/core/blob/dev/homeassistant/components/webhook/__init__.py) accepts a serialized body string and returns inner HTTP status/body/headers. Homestead reuses only an existing authenticated same-server socket. Encryption and typed errors share the HTTP decoder; suitable read/idempotent operations have bounded HTTP fallback. Key creation and notification actions remain single-attempt HTTP, without ambiguous replay.

Scoped subscriptions, Cloud URLs, foreground WebSocket webhook transport, and full registry metadata are optional capabilities with graceful fallback. Safe HTTP(S), originating-server-relative links, and native more-info routing are product policy. `entityId:` is optional Android-compatible URI support, not a mandatory iOS contract. Arbitrary custom schemes are unsupported.
