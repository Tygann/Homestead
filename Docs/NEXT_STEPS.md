Dashboard Home paging now treats saved definitions and local presentation as separate contracts. Saved dashboards and their order remain in the schema-v6 document and iCloud snapshot, while `enabledDashboardIDs` and `selectedDashboardID` are profile-scoped `UserDefaults` values for the current device. Legacy installs enable only the previously selected dashboard; create and duplicate enable the new page without changing the current page; disable, delete, profile activation, and sync reconciliation preserve valid local IDs and choose the nearest preceding enabled page before falling forward. Home uses SwiftUI's native horizontal `ScrollView` paging behavior with a lazy, container-relative dashboard-ID-scoped page per enabled dashboard inside a full-physical-width pager, local dots above bottom navigation when more than one page is visible, and the selected ID driven by the settled scroll target. Each page restores exactly the system horizontal safe area with no additional default spacing, so dashboard content owns its normal padding once and landscape never exposes a neighboring dashboard. The horizontal pager is instantiated only with multiple enabled dashboards; a single dashboard renders its vertical page directly, preserving the original one-page experience without horizontal drag or bounce. A page-styled `TabView` was rejected here because its private paging host clips each nested vertical scroller to the pager's safe-area bounds, preventing dashboard cards from passing naturally beneath the outer navigation and tab bars. The public paging scroll view keeps native vertical under-toolbar travel inside each page, while edit mode disables only the outer horizontal paging scroll view so vertical editing and drag auto-scroll remain available without exposing another dashboard. Its UIKit lock bridge remains dormant during normal browsing and touches the scroll view only when entering or leaving edit mode, preserving SwiftUI's native deceleration and settled targets. The indicator uses a fixed compact four-dot window, shrinks an edge dot when more pages exist in that direction, and places its dots above the platform glass effect so the selected white dot remains legible. The indicator is hosted with Xcode 27's native `safeAreaBar`, allowing SwiftUI to own its bottom inset and scroll-edge integration. Dashboard scrollers rely on SwiftUI's automatic scroll-edge style rather than specifying a redundant hard or soft style; because the outer horizontal pager otherwise reports a permanent top edge, each vertical page forwards only whether it has moved past its native top position so the pager hides that effect at rest and reveals it when content actually travels under the toolbar. The pager—not each page—owns the selected title, dashboard menu, Settings button, and editing completion action, preventing duplicate transition chrome and keeping both primary toolbar controls visible on empty dashboards. Page content, add/edit/remove/icon/rename/reorder actions, item references, suggested setup, and compatibility reconciliation remain explicitly dashboard-scoped. Home's options menu opens the shared dashboard manager directly through `Manage Dashboards`; Home presents it as the root of a scoped sheet with a leading Close control, while Settings continues to push the same view with native Back navigation. The dashboard list exposes a standard Edit/Done toolbar action for native reordering. Settings exposes independent native visibility toggles without changing iCloud page order and prevents disabling the final page. `SettingsDashboardPhonePreview` renders its shared phone, wallpaper, dashboard miniature, and chrome directly at an explicit width-to-height contract without a post-layout scale transform; long layouts remain top-aligned, clip at the phone boundary, and stay behind a persistent mock tab bar in Appearance and dashboard detail settings.
