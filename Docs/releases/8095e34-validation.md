### Deleted-registration finding

HA 2026.10.1 immediately unregisters the webhook when a mobile-app entry unloads; removal records the deleted ID but does not install its HTTP 410 tombstone handler until integration startup. Unknown webhooks deliberately return empty HTTP 200. Homestead rejects that empty body for an encrypted response but does not classify it for bounded registration recovery. Mocked 410 tests therefore do not cover this immediate-deletion path. Do not turn all decryption errors into automatic registration recreation: transport ambiguity and invalid ciphertext require separate treatment.

Source evidence: [mobile-app unload/remove and startup](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/mobile_app/__init__.py), [unknown webhook response](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/webhook/__init__.py), and [mobile webhook tombstone handling](https://github.com/home-assistant/core/blob/2026.10.1/homeassistant/components/mobile_app/webhook.py). No server restart was used to manufacture a passing 410 result.
